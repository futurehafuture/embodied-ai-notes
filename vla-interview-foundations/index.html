00从一次抓取看完整 VLA 闭环

先设定具体任务：桌面上有红色积木，机器人要把它放进左边盒子。相机看到的是像素，关节编码器读到的是当前位置，指令给出“红色”和“左边”的语义。策略必须把三者结合，输出未来一小段动作；控制器再把动作变为受限、可执行的运动。机器人每走几步就重新观察，发现积木滑动或被碰歪时要修正。这条链就是本文后面所有基础知识的共同背景。

完整的一次决策

观测：桌面相机 1 张、腕部相机 1 张，当前关节/夹爪状态与时间戳。理解：视觉编码器提取物体与盒子的图像特征，语言 token 指定要操作哪一个物体和目标。预测：策略生成未来 16 步的动作块。执行：假设控制频率 20 Hz，只执行前 4 步，约 0.2 秒后重新拍照和预测。反馈：若积木没被夹住或被推偏，新的观测应改变下一段动作。这里的“16 步、4 步、20 Hz”是教学算例，不是设备通用参数。

任何一环出错都可能表现为“抓取失败”：相机外参错会抓偏；图像旧帧会追错位置；训练数据没有失败恢复动作会在失误后继续错；动作单位或关节顺序错会朝错误方向动；推理太慢会在两个块之间停顿。因此排障不能只看网络 loss。

近期 VLA 岗位描述反复出现五类工作：训练视觉/语言条件策略、构建多模态数据流水线、定义动作和控制接口、在仿真与真机评测、处理延迟和失败。例如 Agile Robots 的 VLA 工程岗位把这些列为职责，同时要求 Python/PyTorch、机器人硬件或 ROS 经验；偏训练评测的岗位则更强调数据、实验和基准。这是对具体公开岗位的归纳，不代表每家公司完全相同。[1][2]

01数学与机器人学：把动作说成物理量

P0线性代数、概率和优化要服务于具体问题：矩阵乘法与坐标变换、条件概率与似然、梯度与反向传播。机器人部分至少会刚体位姿、前/逆运动学、雅可比、关节与末端两种控制空间。Modern Robotics 的章节可作为系统教材。[3]

1.1 坐标系与 SE(3)

约定 T_AB 把 B 系坐标变成 A 系坐标，则 p_A = T_AB p_B，链式变换是 T_AC = T_AB T_BC。齐次矩阵上左角是旋转 R，右上角是平移 t。要能画出 camera → base → tool 的变换链，分清相机外参方向、姿态表示和米/毫米。ROS 2 的 tf2 正是管理带时间戳坐标变换的基础设施。[4]

T_AB = [ R_AB t_AB ; 0 1 ] p_A = T_AB · [p_B; 1] T_AC = T_AB · T_BC

1.2 运动学、雅可比与控制

前向运动学 x=f(q) 从关节角得到末端位姿；逆运动学从目标位姿找可行关节解，可能多解、无解或接近奇异点。局部速度关系 ẋ=J(q)q̇ 说明为什么同一个末端速度在不同姿态下需要不同关节速度。知道位置、速度、力矩控制各自的含义，能解释策略输出的关节目标为什么仍需底层伺服、限位和碰撞检查。[3][5]

手算 1：一串坐标变换到底怎么乘？

设相机相对基座只平移了 (0.40, 0, 0.20) m，两坐标轴同向；相机观测到目标点 p_C=(0.10, 0, 0.50) m。因为 T_BC 是“相机系 → 基座系”，所以 p_B=T_BC·p_C=(0.50, 0, 0.70) m。若相机旋转了，必须先用 R_BC p_C 再加 t_BC，不能直接相加。

容易犯的错是把 T_CB 当作 T_BC。两者互逆：R_CB=R_BCᵀ，t_CB=−R_BCᵀt_BC。实测时把相机原点代入变换：它在基座系应落在相机安装位置；这个简单检查比盲看矩阵数字可靠。

1.3 用两关节平面臂看懂雅可比

假设两根连杆各长 0.5 m，关节角 q₁,q₂。末端位置为 x=l₁cos q₁+l₂cos(q₁+q₂)、y=l₁sin q₁+l₂sin(q₁+q₂)。对两个关节角分别求偏导，就得到把关节速度映射成末端速度的雅可比。它不是另一套神秘模型，而是前向运动学的局部导数。

J(q) = [ −l₁sin q₁−l₂sin(q₁+q₂) −l₂sin(q₁+q₂) ] [ l₁cos q₁+l₂cos(q₁+q₂) l₂cos(q₁+q₂) ] q=(0, π/2) 时：p=(0.5,0.5)m，J=[−0.5 −0.5; 0.5 0] 若 q̇=(0.2,−0.2)rad/s，则 ṗ=Jq̇=(0,0.1)m/s。

这个结果说明：两个关节方向相反地运动，末端可近似沿竖直方向移动。接近完全伸直时，某些方向的运动需要很大的关节速度；逆雅可比会变得不稳定，这就是面试里常问的奇异位形。工程上会用阻尼伪逆、速度限制或重新规划，但限幅必须由机器人控制层执行。

1.4 策略给目标，控制器负责跟踪

若 VLA 输出的是下一帧关节目标 q*，一个简化的位置伺服可按 q̇_cmd=Kp(q*−q) 计算速度命令；真实设备还有限速、加速度、碰撞和驱动约束。若输出末端增量 Δx，通常还要经过坐标变换和逆运动学/伺服，不能把六维向量直接发给七个关节。动作语义错了，即使离线 loss 很小也会把机械臂带向错误方向。

小实验：先检查动作方向，再检查网络

在仿真或安全低速模式给第一关节一个很小的正增量，记录关节编码器变化和末端移动方向；再逐维检查其他关节。对末端动作分别验证 +x、+y、+z。把结果、坐标系、单位和控制周期写进动作契约。只有这项往返测试通过，才值得训练策略。

面试达标线

给你一个 7 维动作，先追问：七维分别是什么？绝对位置还是增量？相对哪个坐标系？单位和频率是什么？夹爪方向如何定义？再谈模型结构。答不清动作语义，无法判断策略是否能安全执行。

P1轨迹规划、阻抗/力控制、接触动力学、模型预测控制；接触丰富的装配任务会更看重这些。P2全身动力学、步态、抓取稳定性或运动规划，视岗位方向深入。[5]

02视觉：从像素到可用观测

P0掌握针孔相机模型、内外参、畸变、手眼标定、RGB/RGB-D、多相机时间同步。像素不自动等于三维位置：深度、相机姿态和坐标系一致性决定能否把目标位置交给机器人。OpenCV 的标定文档给出了相机矩阵和投影关系。[6]

s · [u, v, 1]ᵀ = K · [R | t] · [X, Y, Z, 1]ᵀ

2.1 从像素反投影到三维

相机内参 K 里的 fₓ,fᵧ 是以像素计的焦距，cₓ,cᵧ 是主点。若有同一像素的可靠深度 Z，可以反投影：X=(u−cₓ)Z/fₓ、Y=(v−cᵧ)Z/fᵧ。所得 (X,Y,Z) 首先处于相机坐标系，还要乘相机到基座的外参才能用于末端控制。没有深度时，一个像素对应空间中的一条射线，不能凭单帧 RGB 唯一恢复距离。[6]

手算 2：像素不是米

设 fₓ=fᵧ=600 px、主点 (320,240)，目标像素 (380,240)，深度 Z=0.50 m。则 X=(380−320)×0.50/600=0.05 m，Y=0，相机系目标点为 (0.05,0,0.50) m。若该像素对应的是物体上沿而非抓取点，还需感知/几何模块确定抓取位置；投影公式只解决坐标，不解决语义。

标定误差会放大为动作误差。例如相机安装后移动几毫米，旧外参就不再代表当前设备；深度反光或遮挡也可能令 Z 错误。用标定板或已知尺寸物体验证重投影误差，再在工作区不同位置检查三维落点，不能只在图像中心验一次。

2.2 图像、状态和动作必须来自同一时刻

策略在 t 时刻收到的应是尽量接近该时刻的图像与机器人状态。设相机 30 Hz、状态 100 Hz、策略 20 Hz，三者不能靠数组索引 i 强行配对；应以采集时间戳取最近观测，并记录两者相差多少。若相机队列积压 200 ms，策略“看见”的物体仍在旧位置，而驱动执行的是当前时刻的动作。即使每路日志都显示正常帧率，也会闭环失败。

age_image(t) = t_policy − t_image_capture Δ_sync(t) = |t_image_capture − t_robot_state| 若 age 或 Δ_sync 超过按任务速度设定的阈值：拒绝动作或保持安全状态。

手眼标定通常要解相机与末端或基座之间的刚体变换；相机固定在腕部和固定在桌面时，变换链不同。固定相机常需 T_base_camera，腕部相机还需使用当前时刻的 T_base_tool(t)。ROS tf2 可以按时间查询变换，但时间戳错误会让正确的矩阵也对应错误姿态。[4]

2.3 深度学习与 Transformer：张量怎样连接

能用 PyTorch 写张量运算、自动求导、Dataset/DataLoader、训练与验证循环；理解梯度下降、AdamW、学习率、过拟合、数据增强、混合精度和 checkpoint。多模态模型还要会算注意力 softmax(QKᵀ/√d)V，分清 self-attention 与 cross-attention、因果掩码与双向注意力、图像 patch token 与语言 token 如何拼接或交互。本站的 大模型面试八股 可补 Transformer 与微调基础。[20][21]

以一批两路相机、每图 224×224 的数据为例：图像张量形状可写为 [B,2,3,224,224]，状态为 [B,S]，文本 token 为 [B,L]。视觉编码器把每路图像变成若干 token；投影层把视觉特征映射到语言主干的宽度；状态可能作为单独 token、连续向量或送入动作专家。进入注意力层前要核对每类 token 的顺序、位置编码和 mask。形状对了但相机顺序错了，模型照样能运行却会学错。

手算 3：注意力为什么要除以 √d？

点积 QKᵀ 汇集 d 个通道，维度增大时数值幅度通常变大。除以 √d 把 logits 的尺度压回相对稳定的范围，避免 softmax 过早饱和。一个长度 N、宽度 d 的序列，注意力权重形状是 [N,N]；多相机和长文本会显著增加 token 数，推理成本与延迟因此成为 VLA 工程问题。[21]

2.4 一次最小训练步实际做了什么

对连续动作的 BC 基线，模型输出与标签形状都是 [B,H,A]。前向计算损失；反向传播把损失对参数的梯度求出；优化器更新参数。验证时必须停止梯度更新，并按完整 episode 汇总指标。下面只展示核心步骤，policy 及数据批次需按具体项目定义：

import torch.nn.functional as F
from torch.nn.utils import clip_grad_norm_

policy.train()
pred = policy(images, state, text_ids)  # [B, H, A]
assert pred.shape == target_actions.shape
loss = F.mse_loss(pred, target_actions)
optimizer.zero_grad(set_to_none=True)
loss.backward()
clip_grad_norm_(policy.parameters(), max_norm=1.0)
optimizer.step()

若训练 loss 降而验证 loss 升，先查数据划分、增强、任务覆盖和训练时长；若两者都降但闭环失败，继续查动作契约、时序同步与分布偏移。微调 VLA 时还应确认哪些模块真的有梯度：冻结视觉编码器、只训动作头、LoRA 和全参训练得到的是不同实验，报告中要明确。

再掌握视觉编码器把图像切成 patch、生成 token 的基本过程；知道多视角图像如何与机器人本体状态、语言 token 融合。VLM 的视觉语义能力不能保证精确控制，接触点、遮挡、反光和视角变化会造成策略输入分布偏移。OpenVLA 使用融合视觉编码器并由语言模型预测动作 token，是一个可读的范例。[7]

能做的检查

随机抽一条 episode：同时显示所有相机画面、时间戳、关节状态和任务文本；确认左右腕相机没有交换、色序和分辨率一致、图像不是旧帧。视觉问题先通过可视化定位，不要直接归咎于“模型泛化差”。

P1目标检测/分割、深度与点云、目标姿态估计、视觉表征预训练。P2触觉、力觉与跨模态融合，视岗位传感器配置而定。

03机器人学习：先会做基线

3.1 行为克隆与分布偏移

行为克隆（BC）用专家轨迹监督 πθ(a|o,l)，最小化动作预测误差。它易实现、适合第一条基线，但训练只见专家状态；部署时一个小错误会让机器人进入未见过的状态，后续错误可能累积。能解释训练误差低、闭环成功率低的原因，以及通过增加纠错示教、在线回采和 DAgger 式数据聚合缓解。robomimic 提供了多种示教学习算法和数据结构。[8][19]

连续动作回归示例：L_BC(θ) = E_(o,l,a)~D [ ||πθ(o,l) - a||² ] 训练集：专家访问的状态 部署：当前策略访问的状态

3.2 为什么预测动作块

逐步回归简单，但多峰示教可能被均值化；一次预测未来 H 步的 action chunk 能降低有效决策长度，也带来块间连续性和反馈滞后的问题。ACT 使用 Transformer/CVAE 预测动作块；Diffusion Policy 将策略建成条件去噪过程；π0 的动作专家用 flow matching 生成连续动作。三者目标相近，训练目标、采样成本和接口不同。[9][10][11]

基线/动作头核心思想面试必须能比较
BC / MLP直接回归当前动作或短块快、易复现；多峰动作易被均值化
ACTTransformer + CVAE 预测动作块块长、执行步数、时间集成、潜变量
Diffusion Policy条件去噪生成动作序列多峰建模、采样步数、推理延迟
Flow Matching学习从噪声到动作的速度场插值路径、速度监督、ODE 采样
离散动作 token量化动作并自回归预测量化误差、序列长度、解码成本

3.3 为什么回归均值会让机器人犹豫

想象桌上有障碍，专家有两条等价路线：从左绕对应动作 a=−1，从右绕对应 a=+1。如果图像不足以区分专家接下来选哪条路线，均方误差回归的最优预测是条件均值 E[a|o]=0。机器人因此直冲障碍或原地犹豫。多峰不是噪声，而是一个观测下存在几种可行行为；CVAE、扩散、流匹配或混合密度模型尝试表示整个条件分布，再采样一条连贯轨迹。

若 P(a=−1|o)=P(a=+1|o)=0.5： argmin_â E[(â−a)²|o] = E[a|o] = 0 0 不是任一专家动作；单点 MSE 小，不保证闭环任务成功。

BC 的第二个问题是状态分布偏移。训练数据里的每一帧都由专家产生；部署时策略做错一步，下一帧就可能不在专家轨迹上。DAgger 的核心是让当前策略访问状态、请专家给这些状态标动作，再把新数据并入训练集。它需要额外标注与安全控制；在真机上常用人工接管和纠错示教实现相近的数据回采思想。[19]

3.4 ACT：动作块、潜变量与时间集成

ACT 不是“普通 Transformer 一次输出很多数”这么简单。训练时，CVAE 编码器读取示教动作序列，得到潜变量 z 的分布；解码器以图像、关节状态和 z 为条件输出未来 H 步动作。训练同时优化动作重建误差与潜变量的 KL 正则；原始 ACT 推理时不再使用动作序列编码器，而使用先验均值作为 z。这让模型能学到人类示教中的不同动作风格。[9]

L_ACT = L_reconstruction(â_(t:t+H), a_(t:t+H)) + β · KL(qφ(z|a_(t:t+H), q_t) || p(z))

预测块长 H 和实际执行步数 k 是两个量。比如策略 20 Hz，预测 16 步覆盖 0.8 s；只执行前 4 步就在 0.2 s 后重新观察和规划。k 小则反应快，但需要更频繁推理；k 大则省推理，但更容易忽视中途扰动。ACT 的时间集成还可把“不同预测块对同一时刻的预测”加权平均；要注意它会平滑动作，也可能增加滞后。

算例：动作块为何不能只看 H

假设每次推理和传输的 95 分位耗时是 140 ms。若每 k=4 步重规划一次，20 Hz 下新块间隔为 200 ms，名义上留有 60 ms 余量；还必须计入图像采集、预处理、排队和动作交接。如果尾延迟变成 230 ms，新块可能在旧块执行完后才到，机器人会停顿。把推理频率、控制频率、H、k 和尾延迟一起报告，才算解释清楚。

3.5 扩散、流匹配与离散 token 的训练目标

Diffusion Policy 给真实动作序列加噪声，训练网络在观测条件下预测噪声（或等价参数化）；推理从随机噪声开始，多步去噪生成动作块。多步生成可以表达多峰分布，但每一步都要运行网络，采样步数直接影响延迟。其项目还采用滚动时域控制：预测一段，只执行前一部分，再重新看环境。[10]

扩散的简化训练式：x_k = √ᾱ_k · a + √(1−ᾱ_k) · ε L_diff = E[ ||εθ(x_k, k, o, l) − ε||² ]

Flow Matching 可取噪声 z 与真实动作 a 的线性插值 x_t=(1−t)z+ta，目标速度为 a−z。网络学会给中间点预测速度，推理时沿这个速度场积分到动作。π0 的动作专家采用连续动作的 flow matching；本站 流匹配笔记有更完整的数学推导。不同论文会采用不同路径、时间方向和损失权重，读源码时必须检查约定。[11]

x_t = (1−t)z + ta，t∈[0,1] L_FM = E[ ||vθ(x_t,t,o,l) − (a−z)||² ]

离散动作路线先把连续值映射为有限个 bin/token，再用自回归模型预测。它可直接借用语言模型的 token 训练形式，却要处理量化误差与多 token 解码延迟。例如把 [−1,1] 均匀分成 256 档，单维步长约 0.0078；这是玩具算例，不代表 OpenVLA 的具体数据归一化和 tokenizer。面试比较模型时先说清动作语义和评测协议，再比较“离散/连续”。[7]

对已有详解，可直接读本站的 Flow Matching、π0/π0.5 和 GR00T；这篇重点是比较框架。

04强化学习：知道何时值得用

P0能定义 MDP：状态、动作、奖励、转移、折扣因子；能区分离线示教数据与在线交互数据，知道 reward 设计、探索风险和样本效率是机器人 RL 的关键约束。已有 PPO 教程 足以补策略梯度与优势估计，但“会 PPO”不等于能解决真机数据问题。

4.1 从“模仿人”到“优化结果”

BC 只问“专家在这个观测下做了什么”，不直接知道任务是否成功；RL 则定义奖励 r(s,a)，优化期望累积回报 E[Σγᵗr_t]。以抓取放置为例，可以在物体进入盒中时给成功奖励 1、否则 0。这样的稀疏奖励很贴近任务目标，但机器人可能大量失败才偶然得到一次正反馈；增加距离奖励又可能诱导“靠近但不松手”等错误行为。这就是奖励设计和探索的实际难点。

同一任务，三类数据

示教数据：人控制机器人完成任务，适合 BC 起步。离线交互数据：已有成功与失败轨迹，可在不继续碰机器人的前提下做离线 RL。在线交互：当前策略在仿真或真机继续采样并更新，能纠正自己的分布，但要承担探索成本和安全约束。三者的训练目标、数据偏差和报告方式不同，不能把“用了历史轨迹”都叫强化学习。

4.2 离线 RL 为什么会高估没试过的动作

价值函数 Q(s,a) 只从数据集中的状态动作对学习。若优化器挑出一个数据中几乎没出现的动作，神经网络对它的 Q 值可能只是外推，却被当成真实高回报；再用这个高估值训练策略会进一步偏离数据。CQL 等方法通过保守地估计未充分观察的动作来缓解这种分布外问题。面试里要说清这是动作分布与价值估计的问题，不等同于 BC 的单步回归误差。[22]

P1理解 BC 预训练后在线微调、离线 RL 的分布外动作风险、人类干预与纠错数据。LeRobot 的 HIL-SERL 教程展示了示教、奖励分类器、人工接管和在线 actor/learner 的组合；它说明了工作流，不意味着每个 VLA 岗位都要求在真机运行 SAC。[12]

人类干预不是简单地“多采一些好示教”。操作者通常在策略即将失败时接管，这些状态恰是当前策略的薄弱处；日志要标出自主段、接管段和接管原因，训练与评测也应区分“自主成功”和“有人救回来”。HIL-SERL 的原始项目展示了将人工干预放入真实机器人 RL 工作流的做法。[23]

一条实用判断

先把观测、动作和成功条件对齐；如果 BC 已能复现示教却在少数状态失败，优先分析覆盖与纠错数据。只有任务有可靠奖励、可控探索和足够交互预算时，在线 RL 才是合适的下一步。

05VLA 架构：从 VLM 到机器人动作

用统一记号描述问题：观测 o_t 包含多相机图像和本体状态，语言指令是 l，策略预测未来动作块 a_(t:t+H)。你要能说清视觉编码器、语言主干、动作头各负责什么，哪些参数训练、哪些冻结，训练标签来自哪里，输出如何反归一化并交给控制器。

πθ(a_(t:t+H) | I_t^1 ... I_t^N, q_t, l) 图像 + 状态 + 语言 → 特征融合 → 动作表示/生成 → 安全适配器 → 控制器

5.1 跟一条样本走完训练与推理

假设任务是“把红色积木放到左边盒子”，数据在时刻 t 有两张图像、当前关节和夹爪状态、这句文本，以及随后 16 步的专家动作。训练时先把图像缩放到编码器所需尺寸，把文本转成 token，状态与动作按训练集统计量归一化；模型根据前三类输入预测 16 步动作，与专家动作计算对应损失并反向传播。部署时没有未来专家动作，模型只看当前观测生成动作块，后处理恢复物理单位，安全适配器检查后只执行前几步，再获取新图像。OpenPI 文档明确状态和动作的归一化必须与机器人动作空间定义对应。[24]

训练样本示意（不是某个模型的固定配置） images: [B, 2, 3, 224, 224] state: [B, S] text_ids: [B, L] target_actions: [B, 16, A] 训练：target_actions 用来算损失 部署：只输入 images/state/text；模型生成 [1,16,A]

“VLA 会语言”需要实验验证。若模型只在一个任务上训练，文本始终相同，它可能完全忽略语言。一个简单的对照是固定图像和状态，交换“放左盒”与“放右盒”的指令，观察动作与闭环成功条件是否随之改变；再与无文本基线比较。若结果不变，不能仅凭模型输入里有文本就声称具备语言跟随能力。

5.2 统一动作表示比统一模型名字更难

跨本体数据可能把动作写成关节位置、关节增量、末端绝对位姿、末端增量或速度；夹爪也可能是二值开合、连续开度或力。把不同数据集直接拼在一起训练，相同第 1 维可能代表完全不同的物理量。训练前要定义标准动作 schema，并对每种机器人实现可逆转换；不相容的自由度需 mask 或专用头处理。Open X-Embodiment 的价值在于跨机器人规模，而可训练性仍依赖数据对齐。[15]

往返测试：防止“模型正常，机器人乱动”

从真实数据取一个动作 a_phys，经过训练端编码/归一化得到 a_model，再用部署端解码/反归一化得到 â_phys。逐维检查 |â_phys−a_phys| 是否在数值容差内，并核对关节顺序、单位、夹爪符号。若用了离散 token，还要单独计算量化误差；若用了旋转表示，还要在姿态空间比较，不能只比欧拉角逐维差值。

读论文的建议顺序：RT-2 看动作 token 如何接到 VLM；OpenVLA 看公开模型和跨机器人预训练；ACT / Diffusion Policy 看没有大语言主干时的强基线；π0 / π0.5 看连续动作专家与分阶段训练；最后用 GR00T 比较数据、架构和部署约束。RT-2、OpenVLA 和 π0 的原始资料都值得逐项核对，而不是背模型名称。[7][11][13]

读一篇 VLA 论文，固定问 8 个问题

任务与机器人是什么？观测有几路、频率多少？动作空间和 horizon 是什么？数据从哪来、怎样混合？损失与采样过程是什么？怎样微调？基线和评测协议是否一致？真机失败集中在哪些条件？

P1LoRA/全参微调、多任务采样、跨本体动作统一、时间条件编码和推理服务。P2世界模型、层级规划、视频预测与开放词汇导航，根据目标团队方向选择。

06数据：VLA 项目的实际起点

一条机器人 episode 至少包含时间对齐的图像、状态、动作、任务描述、终止/成功标签和元数据。LeRobotDataset 的官方格式将多模态时序、视频和索引元信息组织在一起；Open X-Embodiment 展示了跨机器人数据的价值，也提醒我们不同本体的数据必须统一语义后才能混训。[14][15]

6.1 写一份数据契约

  • 观测：相机名称、分辨率、颜色顺序、采集时间、关节顺序、夹爪状态、缺失帧规则。
  • 动作：关节/末端空间、绝对/相对/增量、坐标系、单位、控制频率、动作块长度、归一化统计。
  • 任务：指令与具体 episode 是否对应，成功条件是否可复核，人工干预是否标记。
  • 版本：机器人/相机标定、代码 commit、checkpoint、训练划分、场景与操作者。

6.2 先做数据体检，再训练

画每个动作维度的分布和时间曲线；检查 NaN、异常跳变、图像冻结、时间戳逆序、相机错位、任务文本与实际行为不符。按 episode、任务、场景和物体划分训练/验证/测试，避免同一条示教的相邻帧同时出现在训练和测试中。robomimic 的研究也强调数据质量、状态/动作覆盖会影响策略学习。[8]

6.3 从 episode 造出动作块样本

一个 episode 是按时间排列的观测和动作。训练动作块策略时，在时刻 t 用当前观测预测 a_t,…,a_(t+H−1)。窗口必须留在同一 episode 内；如果跨过复位边界，标签会出现一次“瞬移”，模型却会把它当正常动作。短 episode 可以丢弃、补齐并标 mask，或采用模型要求的边界策略，但必须明确记录。

import numpy as np

def make_action_windows(episodes, horizon):
    observations, targets = [], []
    for ep in episodes:
        obs = np.asarray(ep["observations"])
        actions = np.asarray(ep["actions"])
        assert len(obs) == len(actions)
        assert np.isfinite(actions).all()
        for t in range(len(actions) - horizon + 1):
            observations.append(obs[t])
            targets.append(actions[t:t + horizon])
    if not observations:
        raise ValueError("没有足够长的 episode 可组成动作块")
    return np.stack(observations), np.stack(targets)

# 每条 ep 独立滑窗；输出形状为 [样本数, 观测维] 与 [样本数, H, 动作维]

上面代码故意只演示时间窗口，尚未接图像、语言、时间戳和缺帧处理。真实流水线要先检查各传感器以同一时钟基准对齐，再按控制时刻索引。LeRobotDataset v3 提供统一存储和索引，但“文件能被读到”不等于采集时已经对齐。[14]

6.4 归一化、划分与数据泄漏

若动作维度同时含米、弧度与夹爪开度，直接用统一 MSE 会让尺度大的维度主导损失。常用每维均值/标准差或分位数缩放；只用训练集估计统计量，验证集和真机部署用同一份统计文件。分位数裁剪也要保留物理值到归一化值的确切映射，并观察饱和比例。OpenPI 文档特别提醒，归一化统计与机器人动作空间定义要匹配。[24]

# train_actions: [N, H, A]；只能由训练 episode 构成
mean = train_actions.mean(axis=(0, 1))
std = train_actions.std(axis=(0, 1))
std = np.maximum(std, 1e-6)
normalized = (train_actions - mean) / std
restored = normalized * std + mean
assert np.allclose(restored, train_actions, atol=1e-5)

一个看似漂亮的假结果

一条 500 帧示教随机把 400 帧放训练、100 帧放测试，测试动作 MSE 可能很低，因为两边共享几乎相同的物体、背景和运动阶段。正确做法至少按完整 episode 划分；若要评估场景泛化，还要把整组新物体/新背景/新操作者留作测试。结果表必须写“泛化到什么”，而不是只写“测试集准确率”。

最有说服力的项目证据

展示一个“数据错误 → 可视化定位 → 修复 → 固定评测协议下成功率变化”的完整案例，比只列出模型参数量更能说明工程能力。

07评测：离线 loss 不等于会干活

离线动作误差用于检查训练和接口，但真实闭环指标应包括任务成功率、完成时间、碰撞/安全停止、人工接管次数、推理延迟和跨场景鲁棒性。LIBERO 专门测试机器人学习中的知识迁移；真机实验则需要明确初态分布、复位规则、相机位置、失败判定和试验次数。[16]

成功率 = 成功 episode 数 / 按预定协议运行的 episode 数 比较 A 与 B：固定任务/初态采样/时限/安全参数，报告每类失败数量

一张高质量结果表至少有模型版本、数据版本、任务/场景、样本量、成功数、成功率和失败类别。若只做 5 次，报告 4/5 而不写成“80% 已证明泛化”；小样本不确定性很大。测试集和调参集必须分开，比较模型时尽量使用相同初态与相同硬件条件。

7.1 同一个模型，为什么三个指标会说不同的话

离线动作误差在预录数据上比较预测与专家标签，能发现训练和编码问题，却不知道动作执行后下一帧会怎样。仿真闭环成功率让策略影响未来观测，能暴露分布偏移，但接触和传感器模型未必真实。真机成功率最贴近目标设备，但受复位、磨损、操作者和现场安全约束影响，成本较高。三者应形成诊断链，不能互相替代。

手算 4：8 次成功 / 10 次试验说明什么？

点估计是 8/10=80%。用 Wilson 方法计算，约 95% 区间为 49%–94%；区间很宽，说明 10 次不足以精确区分两个相近策略。报告写“在预先规定的 10 次试验中成功 8 次”，附完整初态和失败录像。若要比较 A/B，最好对同一批预定义初态分别运行，并记录每个初态的成败，而不是让 A 只碰简单物体、B 只碰困难物体。[25]

7.2 预先写协议，避免看完结果再改成功定义

以“红色积木放入盒中”为例：复位时从标记区域随机摆放积木；每次最多 30 秒；积木进入盒内且松开夹爪后保持 2 秒才算成功；人工接管、超时、安全停机分别记为失败类型。冻结 checkpoint、相机位置、任务文本与控制参数，训练和调参用的初态不参加正式测试。这样结果才能被他人重复，失败视频也能指向具体环节。

做消融时一次只改变一个可解释因素，例如“是否有腕部相机”“H=8 还是 16”“有无语言输入”。同一任务下记录成功率之外，还要记录每次端到端延迟的中位数与高分位、动作拒绝次数和接管次数。若某模型成功率更高但频繁触发安全停机，不能只展示成功率。

失败现象先查什么再考虑什么
总是朝反方向动坐标系、动作符号、关节顺序、反归一化模型结构
靠近物体就停顿推理尾延迟、动作块交接、控制超时缩短模型或改采样步数
训练场景好，新背景差物体/背景覆盖、相机视角、光照增强、回采与域随机化
离线 loss 降、真机失败时间对齐、数据泄漏、动作语义、闭环分布偏移新模型与更大数据量

08系统：把策略接到可控的机器人上

P0Python/PyTorch 要能独立写 Dataset、训练循环、checkpoint、配置和评测脚本；机器人侧至少理解 ROS 2 的节点、topic、时间戳和 tf2，以及相机、驱动、策略服务的进程边界。岗位要求通常强调超越 notebook 原型的训练/评测代码。[1][4]

8.1 把慢策略与快控制分开

一个典型结构是机器人端负责读传感器、维护设备状态和执行安全限制，GPU 端负责根据观测预测动作块。比如驱动伺服可能以数百 Hz 到更高频率运行，而图像采集与 VLA 推理通常更慢。策略服务返回的必须是带 episode_id、观测时间戳和模型/动作契约版本的候选目标，机器人端确认它没有过期、维度正确且可执行，才交给底层控制器。OpenPI 的远程推理文档展示了策略服务与客户端分离的做法。[26]

相机/状态采集→时间同步→VLA 服务→反归一化与安全检查→驱动伺服

策略推理是慢环，驱动/伺服是快环；不能把 GPU 返回的动作直接当作电机电流。记录从采集到执行的端到端延迟，区分平均值与尾延迟。动作需检查维度、NaN、单位、限位、碰撞、超时及旧 episode 的返回值。完整上机流程见本站 VLA 真机 Sim2Real。

端到端延迟 = 采集 + 预处理 + 排队 + 网络 + 模型采样 + 后处理 + 下发 若每 k 步重规划，重规划间隔 = k / f_control 秒 新块到达的高分位延迟 + 安全余量 < 可用的旧块覆盖时间

只测“GPU forward 平均 30 ms”远远不够：相机缓冲、网络重试和生成式动作头的采样步数都可能造成尾延迟。策略对 200 ms 旧图像做出的动作，即使模型只花 30 ms，仍然可能追着过去的物体走。监测应同时记录图像年龄、状态年龄、推理 p50/p95/p99、每块实际执行步数与拒绝动作原因。

8.2 Sim2Real 要做可证伪的差异实验

P1在 MuJoCo、Isaac Lab 或其他仿真器中复现相同观测/动作契约；系统性改变质量、摩擦、光照、相机位姿和控制延迟，判断 sim2real 差距来自哪里。仿真分数本身不能替代真实机器人验证。[2][17]

若仿真成功、真机抓取失败，不要一次性随机化所有参数。先录一条真机失败：若目标定位偏移，检查相机内外参；若能碰到物体却夹不住，检查夹爪动作与接触/摩擦；若动作迟滞，注入相同延迟到仿真；若训练时物体总在中央而真机分布更广，重新采初态。每次只改变一个差异，比较前后轨迹与成功率，才能知道哪项仿真改动真正有用。

故障注入练习

在仿真中故意把相机外参平移 2 cm、让策略输入延迟 150 ms，分别记录失败模式。再恢复其中一个因素。若两者都让成功率下降，检查错误形态是否不同；这能训练你把“模型泛化问题”拆成几何问题和时间问题。

真机安全边界

首次运动前由设备和现场流程确定急停、限位、低速模式及人工接管。模型不是安全控制器；网页按钮或 Python 异常也不能替代硬件安全链。具体操作以厂商手册和实验室流程为准。

10用这些问题检查自己

Q1 · VLA 和普通 VLM 的关键差别？

回答应包含动作空间、时序闭环、物理约束和评测方式；只说“加了动作头”不够。

Q2 · 为什么同一个观测可能有多种正确动作？

说明多峰轨迹和均值化问题，再比较 CVAE、扩散、流匹配与离散 token。

Q3 · 动作块越长越好吗？

讲清推理摊销、有效 horizon、块间接缝和反馈滞后；结合控制频率与延迟预算回答。

Q4 · 离线 MSE 下降，但真机成功率不变，怎么查？

按数据/时间同步 → 坐标与反归一化 → 控制接口 → 闭环分布偏移 → 评测协议的顺序定位。

Q5 · 如何证明语言真的被模型使用？

固定图像/状态，更换相冲突的任务文本；加入无语言基线和任务切换评测，观察动作与成功率是否随指令改变。

Q6 · 如何比较 OpenVLA 与 π0？

明确两者的动作表示、训练数据、推理成本、可微调性、机器人接口和同协议结果；避免跨论文直接比较百分比。

Q7 · sim 里 90%，真机 20%，下一步？

对照相机、物理接触、控制延迟、动作语义和初态分布，做单变量实验；不要先盲目增加训练轮数。

11一条可执行的学习顺序

以下按“已有 Python/深度学习基础、目标是机械臂操作方向”设计；周数只是排程示例，是否达标以交付物判断。

  1. 第 1–2 周：机器人 + 视觉。手推坐标变换和雅可比；用一段数据画多相机、关节与动作曲线；能解释每一维动作的物理意义。
  2. 第 3–4 周：BC + ACT/DP。复现两条基线，做闭环仿真与失败归因；不以训练 loss 作为唯一结论。
  3. 第 5–6 周：VLA。精读 RT-2、OpenVLA、π0/π0.5；在统一表格中写出输入、动作、损失、数据和延迟；微调一个可运行模型。
  4. 第 7–8 周：评测与部署。固定评测协议，补失败视频与统计；有设备再做低速真机闭环，否则完成仿真中的部署接口和延迟分析。
能投递的最低证据

一个可复现仓库 + 一份清楚的实验报告 + 一段闭环运行视频 + 一个你亲自定位并修复的失败案例。研究岗再增加有说服力的消融或新方法；工程岗再增加接口、安全、延迟和稳定性证据。
